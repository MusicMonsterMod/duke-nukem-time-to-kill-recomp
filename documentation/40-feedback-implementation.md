## D19A font implementation

Inspected actual glyph pixels from the owned GRP and supplied PNG ZIP. The GRP's
menu art differs from the supplied Atomic set, so the selected source is the exact
SHA-pinned PNG ZIP: Messages (including its Atomic comma override) and Atomic
Edition / Normal (Palette 00). No Doom palette was guessed for the PK3s. Original
PNG palette and alpha are retained; message letters have the original uppercase
shapes even for lowercase input. Atomic intentionally maps lowercase to uppercase
and absent punctuation to `?`. Non-ASCII UTF-8 sequences produce one fallback.

`build_duke_fonts.py` uses only Python's standard library, validates indexed PNG
chunks/filters, and produces deterministic `ttk-fonts.pack` plus a provenance /
glyph-mapping JSON. Both PK3s' supplied INFO, CREDITS and FONTDEFS are preserved in
that metadata (3D Realms; submitter Jimmy). Original archives remain untouched.
CMake generates the local pack beside the executable; generated art stays ignored.
No new redistribution permission is implied.

The shared `duke_font.h` API supports message and Atomic heading styles. Existing
Modernized host messages/status text use the small style. Atomic is available for
headings; no unrelated menu UI was invented. Vanilla keeps the generic host path
and original TTK text. Both renderers share bounded word wrapping and 2x integer
rasterization with nearest texture filtering. Transparent glyphs have a small dark
shadow. Width follows the available renderer space on resize. Missing/corrupt packs
return to the existing generic renderer. The loader checks size, checksum, glyph
bounds and offsets before drawing; `DNTTK_FONT_PACK` is a diagnostic override.

Native raster checks cover both styles, all cheat labels, punctuation/digits,
Unicode fallback, three available widths (304/624/1008), transparency, determinism,
Vanilla and missing/corrupt pack fallback. Very long headings require a caller-
provided taller canvas; insufficient capacity returns zero without writing past it.
The composed native sheet was visually reviewed. Gameplay renderer captures follow below.

Final OpenGL apartment verification (`iteration40-font-gl`) passed a further fresh
concealed landing and exposed pickup. Repeated switch offsets 25, 15, 0, -15 and
15 degrees all toggled its actual state; flags stayed 0x400 and the secret count

OpenGL font review caught the existing compositor's opaque-panel assumption:

transparent glyph backgrounds and readable wrapping at 320x240, 640x480 and
1024x768. `iteration40-font-gl-final` contains all ten confirmations and window
geometry records. Native/asset verification also rejects corrupt and absent packs.


Software review also found that the existing logical-screen presentation softened
new glyphs on resize. The SDL3 Duke-font branch now temporarily draws in output
pixel space at integer scale, saving/restoring logical presentation, viewport,
clip and scale. Legacy/Vanilla text, volume, reticle and other overlays retain
their existing path. The final Software capture run verifies this scoped refinement.
